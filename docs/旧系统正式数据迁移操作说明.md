# 旧系统正式数据迁移操作说明

本迁移适用于 2026-10-31 导出的 `niaosu2020`、`paishui2020`、`shiji2020` 三个旧账套。

## 数据口径

- 客户、供应商：编码或名称已存在则不重复创建，只补齐新系统为空的联系人、电话、地址、税号及银行字段。
- 客户负责人：通过人工映射 CSV 绑定现有账号；无法确认的人员保持未分配。
- 产品/原料：优先复用新系统已有档案；跨账套同名同规格合并；相同编码但不同物品时增加账套前缀。
- 包装：能识别出“25kg/袋”等规格的，补充为产品/原料包装配置；托盘、吨桶等可计数耗材沿用原料库存管理。
- 库存：三个账套先汇总，同一物品按总金额/总数量计算加权成本，再写入一次完整快照。
- 仓库：旧“北京仓库、大小包装主仓库”映射沧州仓库；旧“廊坊工厂仓库”映射廊坊仓库。
- BOM：三个旧库的 `BOM_Ndx`、`BOM_Detail` 均为 0 行，本轮保留新系统已有 BOM，不做覆盖。

## 正式执行前

1. 停止用户录单，进入维护窗口。
2. 将本地生成的迁移数据包解压到项目根目录，确认存在：
   - `old_data/export_20261031/{三个账套}`
   - `docs/legacy_migration_20261031/{映射 CSV}`
3. 备份 MySQL：

```bash
mkdir -p /opt/yecai/backups
mysqldump -u root -p --single-transaction --no-tablespaces --routines --triggers \
  --default-character-set=utf8mb4 yecai_db \
  > /opt/yecai/backups/yecai_db_before_legacy_import_20261031.sql
```

4. 升级结构：

```bash
cd /opt/yecai/yecai-new
source venv/bin/activate
alembic upgrade head
```

## 正式导入

```bash
for name in niaosu2020 paishui2020 shiji2020; do
  python scripts/import_legacy_master_data.py \
    --source "old_data/export_20261031/$name" \
    --skip-conflicts --fill-existing-empty \
    --skip dept,user,warehouse,bom,stock \
    --existing-user-map "docs/legacy_migration_20261031/${name}_user_map.csv" \
    --product-map "docs/legacy_migration_20261031/${name}_product_map.csv" \
    --apply
done

python scripts/import_legacy_packaging_configs.py --apply

# 上线清场后使用完整库存快照：先清零所有旧余额，再写入 209 条汇总结存。
python scripts/import_legacy_inventory_20261031.py --apply --zero-all-inventory
```

## 导入后核对

- 非零库存应为 209 条。
- 沧州仓库 208 条，廊坊仓库 1 条。
- `related_type=legacy_20261031` 的期初库存流水应为 209 条。
- 库存预览 CSV 与数据库数量、移动平均成本应 0 差异。
- 抽查客户联系人、电话、地址及负责人（尤其王飞 `cphw_wangfei`）。
- 检查产品、原料、包装基本信息页面的新增记录。

如任何一步失败，停止服务并从导入前备份恢复，不要在失败状态下继续录单。
