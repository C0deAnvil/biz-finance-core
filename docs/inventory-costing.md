# 库存移动平均成本

适用范围：产品、原料、包装；按「仓库 + 物品」分别核算。无全局启动日。

## 计价规则

- 零库存的成本余额和移动均价均为 0。首次入库以该笔来源单据的成本建立均价。
- 有库存的入库：新成本余额 = 原成本余额 + 本次入库金额；新移动均价 = 新余额 / 新数量。唯一例外是迁移时已有库存：第一次带正价的真实采购入库先用采购单价重估**剩余**期初数量、记录自动成本调整，然后开始正常移动平均。以前已经出库的流水不倒改。
- 出库：按出库前的成本余额和数量计算出库金额；最后一笔出库吸收四舍五入尾差，确保清零后成本余额恰为 0。
- 金额以 `Decimal` 计算，余额和流水金额保留 4 位，移动均价保留 8 位。前端展示不参与记账计算。
- 移库以源仓已过账的出库金额为目的仓入库金额，不能按目的仓或操作员填入的价格重算。
- 采购到货成本取到货单明细，库管执行入库时不能修改单价。
- 生产成品成本 = 已过账领料出库成本 + 任务录入的直接人工 + 制造费用；生产入库一律标记为暂估（如任何原料未定价，则标记待定价）。同一任务不能重复结转。
- 销售退货回库优先按原销售明细的出库成本回转；无法关联明细的历史单据按原订单同产品出库成本回退，不按退货当日的库存均价估价。
- 手工入库的成本视为暂估；盘盈或其他来源如没有可靠成本，则保留待定价状态。

## 历史库存与人工调整

迁移时，有数量的库存沿用原移动均价形成期初成本余额，但标记为「暂估」和「待首采重估」；原均价为零的库存标记为「待定价」和「待首采重估」。**不修改历史出入库流水或历史利润**。财务在「库存状态 → 成本调整」为仍有数量的库存录入单位暂估成本和原因。每次调整保留旧值、新值、数量、操作人和时间；调整只影响当前剩余库存及未来出库，不追改过去的发货成本。期初存货的人工调整不取消「待首采重估」；首次真实采购会按新采购单价替换剩余期初库存暂估价并自动留痕。零库存不允许手工设价，下一次入库自动建立成本。

成本状态：`actual` 表示来源单据已带入成本；`estimated` 表示包含期初、手工或生产暂估金额；`unpriced` 表示仍有未确定成本。多来源混合库存取较保守的状态。销售单全部发货且每笔出库已定价后才计算订单利润；未定价订单的报表成本和利润显示为空，不把未知成本当作零。

## 部署与核验

先备份数据库，再部署后端代码，运行 `venv/bin/alembic upgrade head`（Windows 为 `venv\Scripts\python.exe -m alembic upgrade head`），之后部署构建好的前端。该迁移会改库存与流水精度、增加成本余额/状态、人工调整日志以及生产费用字段。迁移前后应核对各仓库存数量不变、正库存中「待定价」条目，并由财务逐条补录期初暂估价。

本模块不是完整总账：采购价外的运输/装卸等费用须体现在到货成本单价中；销售利润沿用系统现有运包费用口径，退货退款、存货跌价准备及其他期间费用不在本次移动平均库存台账里自动结算。涉及正式财务报表前，仍应由财务核对这些费用与成本状态。

库存周转率等历史期末价值只能从当前成本余额倒推已记录流水；如期间发生人工暂估调整，过去月份的余额会受当前估价影响，不应把该指标当作已结账的历史财务报表。
