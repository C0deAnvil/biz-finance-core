# 正式启用前数据清场说明

## 默认保留

- 组织、角色、用户、页面权限、系统参数
- 客户、供应商、产品、原料、包装、仓库
- 供应商供货目录关系
- 标准 BOM、企业资金账户、收款方式、已登记的打印和扫码设备

## 默认清空

- 销售、采购、生产、质检、退换货、移库、盘点、报销、应收应付等测试单据
- 审批、待办、通知、操作轨迹、附件数据库记录
- 打印任务与扫码处理记录

## 上线前必须确认

1. 当前库存、批次和移动平均成本是真实期初数还是测试数。真实数据使用 `--keep-inventory`，测试数据则一并清空。
2. 供应商样品和质检结果是否属于要保留的供应商评价资料。当前方案把它们视作测试业务数据清空。
3. 企业账户本身会保留；测试期间产生的账户余额流水默认清空。若余额已经是真实期初数据，应在清场后重新登记期初余额。
4. `uploads` 目录先整体归档，不直接永久删除；核对无误后再清理归档。

## 推荐执行顺序

1. 停止后台和本地自动打印、扫码客户端。
2. 使用 `mysqldump` 完整备份数据库，并复制 `uploads` 目录。
3. 运行 `python scripts/go_live_cleanup.py`，只查看每张表的拟删除行数。
4. 确认库存策略及供应商样品策略。
5. 使用带备份校验和确认语的执行命令清场。
6. 执行 `alembic upgrade head`，启动系统，逐项核对主数据、账号、库存期初数和权限。

清场脚本不会删除上传文件；这是故意保留的一道恢复保险。
