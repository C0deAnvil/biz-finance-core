# 产品、价格库存与收付款账户更新

## 行为

- 销售单产品选项显示“产品编号 - 产品名称 - 规格”，可按编号、名称、规格筛选。
- 产品页面与标准价格页面共同读取 `products.price`，系统没有另一张保存当前标准价的表。`standard_price_change_logs` 只存变价历史。
- 订单金额按该订单的 `sales_order_items.unit_price × quantity` 计算，选品时带入当前标准价；零价样品、经审批改价仍然允许。订单成交价属于历史交易数据，标准价变化不会重算旧订单。
- 产品主表不存实有/占用库存。产品页面从 `inventories` 汇总成品仓库存，与库存状态页面共用可用量函数：实有 − 占用。比较时请在库存页面选同一成品仓范围；在途数量不计入当前可用库存。
- 新建产品默认贸易型；迁移只改默认值，不自动重分类已有产品。
- 新增“财务管理 → 收付款账户”：财务维护企业、客户、供应商账户，支持多账户、启用/停用。账号作为字符串保留前导零。
- 销售单笔/合并收款确认时选择企业收款账户，财务审核直接核对该账户；接口也会阻止换成另一个账户。旧申请没有账户时，财务可以补选。
- 采购单笔/合并付款申请必须选择该供应商启用的收款账户。财务保留该收款账户，并选择企业付款账户。供应商管理的“账户”入口支持采购维护多个收款账户，也支持财务维护。
- 企业账户的参考余额 = 系统内已确认收款 − 已登记付款。未确认申请不计入，重复确认不重复记账。参考余额允许负数，不限制付款，不代表银行真实余额；当前结算使用 CNY 账户。
- 财务账户目录支持修改资料、停用账户、查询账户流水、余额调整和企业账户间转账。调整和转账写入 `financial_account_transactions`，余额调整只影响参考余额；历史单据引用过的开户身份信息不能直接改，需停用旧账户后新增。
- 保存销售单时，如果收货地址与客户档案不同，会询问是否同步。选择“是”时地址和订单在同一事务中保存；选择“否”时只保存订单地址。已有其他人修改客户地址时会提示刷新，避免覆盖。
- 历史收付款记录关联账户档案。账户户名、开户行、账号不直接改写；发生变更时停用旧账户、新建账户，保留旧单据追溯。
- 旧供应商档案中同时具有开户行和账号的记录会迁入账户表。企业/客户账户由财务录入，不自动猜测。旧单据无账户时仍可查看，后续登记时补齐。
- 往来账户可供查询开票资料；实际发票的抬头、税号仍使用客户/供应商档案。此次不新增开票业务流程。

## 服务器部署

本次包含数据库结构变化，不能只 `git pull`。以下命令在服务器项目目录执行：

```bash
git pull
# 使用运行后端的同一个虚拟环境，并确认其 DATABASE_URL 指向正式业务库
source venv/bin/activate
alembic current
alembic upgrade head
alembic current
cd frontend
npm ci
npm run build
```

本次新增迁移版本为 `c5d6e7f8a9b0` 和 `d6e7f8a9b0c1`，上一版本为 `b4c5d6e7f8a9`。迁移创建 `financial_accounts`，为收款申请、付款申请、收款记录和付款记录增加账户外键，创建账户流水表，修改产品类型默认值，并迁入旧供应商账户。无需手工逐条执行建表 SQL，也不要用 `alembic stamp head` 替代升级。

迁移前按现有方式备份数据库；执行期间暂停后端写入。迁移、前端构建完成后，使用现有服务管理方式重启后端；本文件不猜测服务器服务名称。重新登录以更新菜单，由财务先维护企业账户，再提交新的收付款业务。

## 批量修改现有产品类型

使用 `scripts/reclassify_products.sql`。先执行预览查询，确认名单；生产型判定为名称包含“尿素”且不包含“球”，或名称包含“铜丝”。其他产品为贸易型（包括其他试剂、球状/球体/球形尿素）。

核对后在同一个 MySQL 会话执行事务内 UPDATE 和统计，再手动 `COMMIT;`；不符合预期则 `ROLLBACK;`。该文件默认不提交事务，不能将整份文件通过管道执行后就认为修改已生效。

此 SQL 仅改产品档案，不会改历史订单、采购单、生产任务或已生成补货需求的类型。涉及这些单据的后续处理仍按原单据记录进行。
